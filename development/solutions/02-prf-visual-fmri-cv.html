Practical 2: Cross-validation#

Download notebook

This is the notebook for the second practical of the workshop. This practical covers how to evaluate the out-of-sample model fit using cross-validation on empirical data from visual functional magnetic resonance imaging (fMRI) experiments. It uses the canonical Gaussian 2D population receptive field (pRF) model as an example and illustrates cross-validation across different runs and sessions from the same experiment.

We recommend first going through the first practical because this practical builds on package-specific basics that are covered there.

We also recommend going through this notebook before starting with the notebooks of the other practicals which build on this one.

In computational modelling, cross-validation is typically used to evaluate and compare the ability of different models to generalize their predictions to new observations. That is, from a set of candidate models, we want to select the model which can generalize best to unseen data. Here, we focus only on the cross-validation part and leave the model comparison and selection part to the next practical.

As all computational and machine learning models, pRF models can overfit the data that they are “trained” on (i.e., the data they are fit to in order to estimate their parameters). Overfitting means that the pRF model fits noise in the training data that is not present or different in unseen (i.e., test) data. It leads to a degradation in prediction performance from the training to test data. The more free parameters a model has, the more flexibly it can fit to noise in the training data and the more likely it is to overfit. While some degree of overfitting is unavoidable, we want to at least know when a pRF model overfits and whether we can trust that it is modelling a robust pattern in the data and not just noise. When comparing different models, we also want to be sure that a model leads to better predictions because it captures the underlying pattern in the data better and not just because it fits better to noise in the data (e.g., because it has more parameters).

Fitting the model#

We create a canonical Gaussian 2D pRF model with a custom impulse response submodel to fit to the training data. The repetition time (TR) for this dataset is 1.2 seconds.

from prfmodel.impulse import DerivativeTwoGammaImpulse
from prfmodel.models.prf import Gaussian2DPRFModel

# Define repetition time (TR)
tr = 1.2

# Create custom impulse model
impulse_model = DerivativeTwoGammaImpulse(resolution=tr)

# Define pRF model with custom impulse response submodel
prf_model = Gaussian2DPRFModel(
    impulse_model=impulse_model,
)

Exercise 6 (optional)

Why do we need to create a custom impulse response model with the TR of the dataset? Read the relevant Important Details section.

Solution

The impulse response describes how the BOLD signal unfolds over time in seconds: It peaks about 5 seconds after neural activity and returns to baseline after about 20–30 seconds. The model convolves the impulse response with the predicted neuron population activity, which has one value per time frame. For the convolution to be correct, the impulse response must be sampled with the same time step as the stimulus and the data, that is, once per TR. If we sampled it every second instead, every sample of the impulse response would be interpreted as one time frame of 1.2 seconds. The predicted BOLD response would then be stretched in time: For example, the peak 5 seconds after the activity would end up 5 time frames (6 seconds) later.

To keep things simple, we only use grid search and least-squares in this example to fit the pRF model to the training data. We start by defining ranges of the grid search.

from prfmodel.fitters import grid_values_2d_prf

grid_param_ranges = grid_values_2d_prf(
    stimulus_train,  # We use the stimulus from the training data
    num_mu=21,
    mu_extent=2.0,  # Span twice the visual field covered by the stimulus
    num_sigma=10,
    sigma_range=(0.05, 4.0),  # Log-spaced by default
) | {  # Add constant parameters
    "weight_deriv": [-0.5],
    "baseline": [0.0],
    "amplitude": [1.0],
}

grid_param_ranges

Then, we create the GridFitter and run the grid search on the timecourses of the selected vertices.

from prfmodel.fitters import GridFitter

Yes. Most pRF centers lie inside the stimulus and in the right half of the visual field, which the left hemisphere represents. However, about a third of the vertices have a center on the edge of or outside the stimulus. About 11% of the vertices have a sigma at the floor (0.05 degrees) and about 7% at the ceiling (4 degrees) of the grid.

We should not interpret the parameters of these vertices at face value:

  • Center on or outside the stimulus edge: The stimulus never covers the pRF center, so the data only constrain the center weakly. Many of these vertices also have a response that is dominated by noise. We usually exclude them from the interpretation.

  • sigma at the ceiling: The best fitting size may lie beyond the grid, so the estimate is only a lower bound. We can extend the grid or exclude these vertices.

  • sigma at the floor: The size is smaller than what the stimulus can resolve (e.g., the width of the bar), so the estimate is only an upper bound. Very small pRFs are also often a sign of a noisy fit.

Same stimulus, new session#

To assess the out-of-sample model fit, we first evaluate its predictions on the first run of the second session. The subject saw exactly the same stimulus as in the training run. What differs is the noise in the measurement and everything that changes between sessions, for example, the position of the head in the scanner, the alignment of the data to the anatomy, and the state of the subject. This tells us whether the model captures a pattern in the responses that we can reproduce in a new measurement, and not just the noise of the training run.

We load the dataset for this run using the split argument.

dataset_test_ses = load_dataset("3t-chn-visual", split="ses-02_run-01", task="fixedbar")

stimulus_test_ses = dataset_test_ses.stimulus

response_test_ses = dataset_test_ses.response

# Select the same vertices as for the training data
response_test_ses_valid = response_test_ses[response_is_valid]

Both are identical. Thus, the model with the training parameters makes exactly the same predictions for the training and the test data. Any difference in prediction performance must come from differences in the observed responses:

  • Noise: Thermal and physiological noise (e.g., breathing and heartbeat) differ between the runs. The model is partly fitted to the noise of the training run, which does not repeat in the test run.

  • Session: The position of the head in the scanner, the alignment of the data to the anatomy, and the scanner itself (e.g., drifts and calibration) differ between sessions.

  • Subject: The state of the subject, for example, attention, fatigue, and how well they fixated, can differ between sessions.

For most vertices, the test R-squared is somewhat lower than the training R-squared (the points lie below the identity line), and the mean R-squared drops from about 0.22 to 0.19. The model was fitted to the training run, including part of its noise. The test run contains different noise, so this part of the fit does not carry over. For the best vertices, the predicted peaks match the peaks in both runs, but the noise between the peaks differs.

The R-squared compares the squared errors of the prediction with the variance of the observed response around its mean. When the prediction is worse than simply predicting the mean of the test response, the R-squared becomes negative. This cannot happen for the training data because least-squares can always set the amplitude to zero and the baseline to the mean. It can happen for the test data, where the parameters are fixed. About a third of the vertices have a slightly negative test R-squared. They almost all have a training R-squared close to zero: The model fitted noise in the training run, and this noise prediction only adds errors in the test run.

Fitting and interpreting the final model#

Cross-validation is primarily used for comparing the out-of-sample performance between different candidate models and selecting the model that best generalizes to new observations. Model comparison and selection will be part of the next practical.

Once we have selected a model, our goal changes: We no longer want to evaluate the model but to estimate its parameters as precisely as possible so that we can interpret them. For that, we want to use as much data with the least amount of noise that we can get, including the data that we held out for testing before. This means that there is no held-out data left to evaluate the final fit, and that its in-sample R-squared is optimistic for the same reasons as above. We accept this because cross-validation has already told us how well this model generalizes to new data.

For the CHN dataset, we can for example average the BOLD responses of the two runs that show the identical stimulus (the first runs of both sessions) and fit the pRF model on the averaged responses.

Exercise 16

Why is averaging the responses across sessions a valid choice for this dataset?

Solution

Both runs show the identical stimulus with the same timing, and the responses of both sessions are given for the same vertices of the same surface. Thus, the stimulus-driven part of the response is the same in both runs at every time frame, whereas the noise is independent between the sessions. Averaging keeps the stimulus-driven response and reduces the noise (for independent noise with equal variance, the noise variance is halved). This assumes that the pRFs of the subject do not change between the sessions and that the data of both sessions are well aligned to the same anatomy.

Exercise 17

Why can we average the first run of the first session with the first run of the second session, but not with the second run of the first session?

Solution

The second run of the first session shows a different sequence of bar positions. At the same time frame, the bar is at a different position than in the first run, so the stimulus-driven responses of the two runs differ. Averaging them would mix the responses to two different stimuli into a timecourse that does not belong to any stimulus, and the pRF model could not predict it with either design matrix. To use both runs, we can instead fit the model to both runs at the same time, for example, by concatenating their design matrices and responses along the time dimension.

Summary#

  • The in-sample (training) R-squared is an optimistic estimate of how well a pRF model describes the data because the model is partly fitted to noise in the training data.

  • Cross-validation evaluates the model on data that it was not fitted to. What the test data has in common with the training data determines which kind of generalization we test: A new session with the same stimulus tests whether the model captures a pattern that we can reproduce in a new measurement; a new stimulus tests whether the model captures how a vertex responds to stimulation in different parts of the visual field.

  • The out-of-sample R-squared also depends on the noise in the test data. It can be negative when the model predicts the test data worse than the mean of the test data.

  • We use cross-validation to compare models and to select vertices for which we can trust the parameter estimates. To interpret the parameters, we fit the selected model to all comparable data.
